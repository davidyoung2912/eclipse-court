# Longevity plan: depth, rewards and reach

Status: **phases 1-17 done; phase 18 partly done (Campaign and Lobby moved, language setting added).** Written 2026-10-28 from the full-game review. Each phase is one commit; stop after each so the context can be cleared. Do not start the next phase until asked.

## Ground rules

- Engine rules (`src/engine/rules`) do not change unless a phase says so; if one does, run `npm run modes`, `npm run courts` and `npm run styles` before and after and note the win rates in the commit.
- New text goes through `t()` in `src/i18n/en.ts`. New state lives in its own `eclipse-court:*` localStorage key, parsed safely (`parseX(raw)` pattern as in `shop.ts`), included in backups, with a test.
- Every new effect respects `reduceMotion` and `flashesReduced`; new aids follow the play-aids fairness rules (hidden in scored games).
- Pure rules go in small tested modules; drawing stays in components.
- Verification per phase: `npm run test`, `npm run lint`, `npx tsc -b`, `npm run build` (no browser testing). Commit and stop.

## Part A: Foundations (quality of life)

### Phase 1: Accessibility quick wins
Items 1-3 of `docs/accessibility-plan.md` phase 1.
- Allow pinch zoom: drop `user-scalable=no` from the viewport meta. Read the CSS for fixed heights or `overflow: hidden` that would break at 200%.
- Board focus: keep `svg.board:focus { outline: none }` only because the cursor is drawn; make `.kb-cursor` high contrast in every theme and add a visible focus ring on the board frame when focused.
- Lint: turn on oxlint's `jsx-a11y` plugin in `.oxlintrc.json` and fix what it reports (no new dependency).

### Phase 2: Rematch and Goals hub
- A **Play Again** button on the game-over dialog for skirmish, practice and hot-seat that restarts with the same setup and a new seed (swap sides optional). Not shown for daily, weekly, ladder, campaign, puzzle, online.
- A **Goals** screen (linked from Stats and the main menu's Suggested card) that lists, in one place, the closest-to-complete items from mastery tracks, piece goals, achievements and bounties, with a progress bar and a button to the screen that advances each. A pure `goals.ts` model builds the list; tested.

### Phase 3: Balance guard
- Turn the sim scripts into a fast test: a seeded, small batch (`src/sim`) per mode and per court that fails if a court's win rate or a play style's score leaves a band (about 40-60%). Keep it under a few seconds; the full scripts stay for deep runs.
- Document the bands and how to rerun the full scripts in this plan's Status.

## Part B: Economy and return reasons

### Phase 4: Shard sinks
- Gauntlet **reroll token** (reroll one reward offer, costs Shards, limited per run).
- Daily **streak freeze** (protects one missed day, bought, max 2 held).
- **Extra hint** packs for puzzles (the free hint count is unchanged).
- **Prestige tiers** for owned cosmetics (cost rises, adds a small animated flourish; data on the cosmetic).
- A `sinks.ts` store and a Collection section; prices tuned so the average earner reaches each tier in a few weeks.

### Phase 5: Quests
- Three daily and three weekly quests across all modes ("win a duel in the dark", "solve 3 puzzles", "clear a Gauntlet stage"), each with one reroll per day. Seeded by date (`dailySeed`) so they are the same offline.
- Progress is counted from the existing `Summary` and puzzle/Gauntlet events; claimed rewards pay Shards and season XP (phase 6).
- Shown on the main menu's Today section and on the Goals hub.

### Phase 6: Season track
- A month-long 30-tier reward track filled by XP from games, puzzles, quests and Gauntlet stages. Rewards: Shards, cosmetics, persona-card flourishes and a final season banner.
- Season boundaries come from the calendar (like `events.ts`); the finished track is kept in a history fold.
- Local only: state in `eclipse-court:season`, backed up with the rest.

## Part C: Gauntlet depth

### Phase 7: More relics and event nodes
- Grow `RELICS` from 6 to about 20, with a few that interact (for example one that rewards casting, one that rewards holding beacons), unlocked on the existing `RELIC_UNLOCK_WINS` curve and by ascension clears.
- Add **event** rewards: a choice screen with risk and reward (sacrifice a piece for a relic, trade max HP for a spell). New `Reward` kinds in `gauntlet.ts`; tests for every outcome.

### Phase 8: Branching map
- Replace the linear 8 stages with a layered map: each step offers two or three nodes (fight, elite, event, rest, boss). A pure `gauntletMap.ts` builds the map from the run seed; run codes still reproduce a run.
- Elite nodes are harder and pay more; the final node is a boss drawn from the ladder bosses. `Run` gains a `path`; old saved runs are discarded or finished on the old rules (`RUN_VERSION` bump with a parse test).

### Phase 9: Heat and endless
- A **heat** list beside the fixed ascensions: the player picks penalties (for example fewer spells, hardened elites) that raise a heat score and the reward multiplier.
- **Endless** after the final boss: stages keep scaling through `stageFoe` with a depth record and a share code.

## Part D: Characters and story

### Phase 10: Persona memory
- Record the head-to-head result against each persona (`personaRecord` store). Greetings, briefings and result lines choose a variant by record (first meeting, you lead, they lead, rematch after a loss).
- Add the extra line categories to `personaLines` with the existing "no repeats, at least N per category" test.

### Phase 11: Grudge matches and mini-arcs
- A short arc per persona (three fights with a signature army or rule each) unlocked by beating them, with a Shard prize and a cosmetic at the end. Data in a new `personaArcs.ts`; fights run through the existing scenario/ladder machinery.
- A **Grudge match** button on the result screen after a loss to a persona.

### Phase 12: Story epilogues
- A short epilogue chapter for each of the three endings, readable from the Story screen once that ending is chosen, with a small lasting change (menu sky variant or a cosmetic). Reuse the chapter reader and `endings` set; tests that every ending has one.

## Part E: Social play without a server

### Phase 13: Ghost challenge
- A code that encodes your daily or weekly result and its game record; a friend plays the same game and sees both scores side by side. Built on `shareCard`, `share.ts` and `challenge.ts`; accepted on the Paste a Code screen.

### Phase 14: Tournaments
- **Hot-seat tournament** for 4 to 8 local players with an auto bracket, pass screens between games and a final winner card.
- **Persona tournament** for solo play: an 8-opponent bracket of the personas, with a Shard prize and a trophy record on Stats.

### Phase 15: Puzzle packs
- Export several editor puzzles as one pack code or URL; import checks every puzzle is solvable (the existing check), then lists the pack on the Puzzles screen with its own progress.

## Part F: Variety and shareability

### Phase 16: Layouts and rule seasons
- A **randomized layout** option in Skirmish setup (a mirrored shuffle of the army within legal squares, seeded, checked by the existing setup validation).
- A **featured ruleset** each month (a mode plus a twist) applied to the daily, weekly and ladder games as the season theme; named on those screens.

### Phase 17: Highlights reel
- A "Game of the Week" built from `moments.ts` and the replay data: the best finished game of the last seven days, with a Watch button and a share link. Pure selection model, tested.

## Part G: Reach and code health

### Phase 18: Localization
- Finish moving the remaining screens (Skirmish setup, Gauntlet, Campaign, Story, Stats, Ladder, Lobby, Editor, Replay, game screen, trays, duel, tutorial, tips) and the engine's name and blurb strings behind `t()`.
- Add a language setting that calls `setLocale`; a test that every key used exists in `en.ts`.

### Phase 19: Split the big files
- Break `Game.tsx` and `App.tsx` into per-concern modules (screen routing, game session, result handling) with no behaviour change; the existing tests are the guard.

### Phase 20: Remaining accessibility
- Phases 2-5 of `docs/accessibility-plan.md`: keyboard and focus, time and announcements, contrast script, statement. Each sub-phase is its own commit.

## Suggested order

1 first (cheap, a real WCAG gap), then 4-6 (the return loop), 7-9 (the Gauntlet), 10-12 (characters), 13-15 (social), then the rest. Phases 2 and 3 can move earlier if balance or goal clarity becomes the bottleneck.

Phase 3 done: `src/sim/balance.ts` and `balance.test.ts` run a seeded batch of AI-vs-AI games (about 30 seconds, in its own file so Vitest runs it beside the others; real games cost 0.2-1s each, so "a few seconds" was not reachable). Court bands: each of Beacons (8 games), Leader Capture (8), Score Race (16) and King of the Hill (16), with events and the showdown on, must give Solari between `50% ± (10% + 1.5 standard deviations of sampling noise)`, so the target is 40-60% and small batches only fail on a real skew (for 8 games that is about 13-87%, for 16 about 20-80%, tightening as the batch grows). Draws count half. Style band: every play style scores 20-80% over Score Race and King of the Hill with every pairing from each court at Normal (the full run showed 37-64%). Every game must finish. The seeds are fixed, so a failure means a rule or AI change moved the results, not luck: rerun `npm run courts`, `npm run modes` and `npm run styles` (add `--games 60` or more) and judge the larger sample before moving a band. A first try at seed 3 with 10 Beacons games scored Solari 15% while a 30-game run was 14/16, which is why the bands widen with the noise and the batches use the scripts' seed 1.

The Collection has a Shard shop section at the top. Prices are a guess against about 15 Shards a game and 100-200 a day; revisit after play data.

XP comes from the same events the quests count (a win 20, 25 on the daily, a loss 8, a puzzle 4, a Gauntlet stage 8) plus a claimed quest (15 daily, 40 weekly), so quests now pay season XP as well as Shards; steady play of three games, three puzzles and a quest a day finishes the track before the month ends. Every tier pays 8 + tier Shards; tiers 5, 15 and 25 also give a paid cosmetic from the cheap, middle and dear price bands (drawn by month; if already owned it pays half its price instead), tier 10 a streak freeze, tier 20 a puzzle hint pack (40 Shards instead if the shelf is full) and tier 30 a month-named banner and 100 more Shards. Phase 7 done: `RELICS` has 20 relics. Eleven open by gauntlet runs won (the old 1-6 curve, then Swift Sun 7, Looking Glass 8, Wild Die 9, Cutpurse's Charm 10, Harbinger 11) and nine by opening an ascension level (`RELIC_UNLOCK`; Ironheart and Scholar's Lens at 1, Waystone and Ember 2, Echoing Chalice and Beacon Lamp 3, Conjurer's Seal and Deathbell 4, Ashen Ring 5). Engine rules did not change: the new relics either set existing `MatchConfig` fields (reverse, suddenDeath, showdown, mayhem, freeCast for the player only, short day) or work on the run between fights. The interacting ones read the finished fight: **Echoing Chalice** gives the Leader +1 max HP after a won fight in which a spell was cast (`lastCast`), **Beacon Lamp** gives an extra win to each of your pieces standing on a beacon, **Ember** carries the best lost piece back into the army, **Waystone** puts a camp after every stage but the boss, **Scholar's Lens** offers four rewards, and **Ironheart** adds 1 HP to your pieces in the fight only (subtracted again in `carried`, so it is never banked). Legacy skirmishes get the match-setting relics but not Seal (no court is passed) or the run-only ones. **Events**: a new `event` reward opens a choice screen (`Run.event`, null on old saves, no version bump): the Bone Altar (give up a piece for a relic), the Moon Pact (the Leader loses 1 max HP, floor `MIN_BONUS` -2, for a spell) and the Wayside Shrine (even odds of an Elite perk or losing the strongest non-Leader piece). Outcomes are seeded from the run and stage, so a run code still reproduces them; an event is offered only when it can do something. A run piece's `bonus` may now be negative (down to -2). No win rates were rerun because no match rule changed, but Deathbell, Ashen Ring and the mayhem relics are untested for balance beyond the soak game.

Phase 8 done: `src/engine/data/gauntletMap.ts` builds the map from the run seed and ascension (`buildMap`): eight layers, each of two or three nodes chosen freely (no edges between layers), every layer holding at least one fight or elite. Layer 1 is fights only, elites start at layer 3, camps are nodes (none from ascension 2; below that layer 7 always has one) and layer 8 is the boss alone. `Run` gains `path` (the node taken in each layer; `RUN_VERSION` is 2 and older saved runs are discarded by `readRun`, which also checks the path against the map). `stage` is still the layer number, so stats, quests and the saved fight work as before. A fight, elite or boss node waits to be fought (`runFoe` gives its foe); an event node opens its event screen and a camp node deals its offers at once, both moving straight on. An elite is one difficulty step harder with +1 HP, one more rule and one more piece, pays one more reward and double stage Shards. The boss is one of the three ladder bosses (`runBoss`, drawn by seed) with its signature rule retargeted to the foe's court, plus the usual early Eclipse and showdown. `restStages` is now only the Waystone's camp after a won fight (the fixed camps after stages 3 and 6 are gone). The Gauntlet screen has a choose-your-road step and a list of the whole road. Tests cover the map's shape over 80 seeds, each node kind, elites, bosses on either court and the save check. No match rule changed, so no win rates were rerun; the boss fights now use the ladder bosses' rules and are untested for balance beyond the soak game.


Phase 9 done: **Heat** is seven optional penalties chosen on the Gauntlet start screen (`HEATS` in `gauntlet.ts`: Packed Ranks 1, Thick Hides 2, Hardened Elites 2, Thin Book 2, Lean Spoils 1, No Second Thoughts 1, Falling Dusk 1). Each point adds 10% to the Shards a run pays (`heatShards`, on stage and win Shards). `Run.heat` holds them; old saves read as none with no version bump. They ride in the run code as `G2h<mask>-<seed>` (bit order is `HEAT_IDS` order, which must never change; codes without heat are unchanged), and a typed code overrides the toggles. The daily run takes no heat. Foe effects go through a new trailing `heat` argument of `stageFoe`; Thin Book trims the starting spells, Lean Spoils trims offers (floor of two), No Second Thoughts turns off `canReroll`, Falling Dusk caps `eclipseRound` at 24 in `stageGame`. **Endless**: beating the boss now keeps the won run (stage 9) and shows a "run is won" screen with Go Deeper or End the Run; the win, its Shards and its stats are paid at the boss as before. `enterEndless` sets `Run.endless` and deals spoils; from then on each fight is a depth with no map choice (`endlessKind`: every fourth a ladder boss in turn, every other a elite, else a plain fight). `stageFoe` past stage 8 keeps scaling: +1 HP every two depths, one more rule every two depths (up to two, total capped at five), hard AI. A loss or walking away in Endless does not count as another run; it records the depth (`endlessBest` in the ascension store, `recordEndless`) and shows a summary with the run code. A saved Endless run may be up to 500 fights deep. No match rule changed, so no win rates were rerun; deep Endless fights are untested for balance beyond the foe-shape tests.

Phase 13 done: a **ghost** is a daily or weekly result sent as a code (`src/engine/ghost.ts`: `encodeGhost`/`decodeGhost`, link kind `x`, also accepted as a bare code on Paste a Code). It holds the kind, the day (or the week's Monday) as a `dailySeed`, won/draw/turns/lost and, where it fits (6000 characters), the game as a record code. The match itself is not in the code: `ghostMatch` rebuilds it from the date with `dailyMatch(date)` or `weeklyMatch(date)`, and a record that does not start from that match, a date that is not a day or not a Monday, or out-of-range numbers are refused. Both kinds score on the weekly scale (`ghostScore`), so two results compare. `src/ghosts.ts` (key `eclipse-court:ghosts`, in backups, parsed by `parseGhosts`) keeps the game behind the day's first scored daily and the week's best weekly so a code can carry it. The Daily and Weekly screens have a **Send as Ghost** button once a result exists. The Ghost screen shows their result beside yours (from the daily result or the week's best, if that day or week was played here), a **Watch Their Game** button when a record came along, and **Play This Match**: an unscored game of the same match against its named AI (`ghost` on the game screen keeps it out of the daily, the weekly, bounties and difficulty advice; not resumable) whose result dialog says whether you beat the ghost. If the ghost is the current day or week, **Play It for the Record** goes to the real Daily or Weekly screen instead. Not done: a ghost for the ladder, Gauntlet or puzzle results.

Phase 14 done: `src/engine/data/tournament.ts` is the pure single-elimination model (`newBracket` deals a seeded order and gives byes to the first entrants when the count is not a power of two; `report`, `nextMatch`, `champion`, `simulate`, `cleanNames`) and `src/tournaments.ts` the store (key `eclipse-court:tournaments`, in backups, parsed by `parseTournaments`, which replays the saved results against a fresh bracket and drops a bracket that does not fit). The new **Tournaments** screen (Battle menu) offers two kinds. **Hot-seat**: 4 to 8 named players, an auto bracket, and a pass card before each match naming who plays Solari and Umbral and who gets the device; a drawn game is replayed with the courts swapped and a second draw goes to the first side; the end shows a winner card and the whole bracket stays on screen. Hot-seat games are skirmish-classic rules and touch no stats. **Persona Cup**: you and seven personas (one sits out, drawn by seed) over three rounds; the matches between personas are decided by a seeded coin up to your next match, the first round is Normal and later ones Hard with the persona's style, and the final has the showdown. Each win pays 10 Shards and the Cup adds 150; a draw is replayed; a loss ends the run and names the winner. The Cup record (entered, won, finals) shows on Stats beside "Tournaments won". Match games run as `tourney` game screens: not resumable, outside bounties, quests, the persona record and difficulty advice; quitting a match leaves the bracket as it was. Phase 15 done: `src/engine/data/pack.ts` is the pure model (`encodePack`/`decodePack`, `packId`, `validPuzzle`, `puzzleGoal`) and `src/packs.ts` the store (key `eclipse-court:packs`, in backups, parsed by `parsePacks`): the packs kept, each with the indexes solved, and the editor's draft. A pack is a name (24 characters) and 1 to 12 puzzles, shared as a link of kind `p` (also a bare code on Paste a Code). "Solvable" here means the same checks the editor and challenge codes already make: every puzzle must be a valid config from the editor, a puzzle goal (survive, escort or hold), Solari's side, and free of every `problems()` the editor reports. There is no search that proves a board can be won; an unwinnable board the editor accepts is still accepted. The Editor has a Puzzle pack section (add the current puzzle, remove, name, Copy Pack Link, Keep as a Pack, Empty). Opening a pack link shows its puzzles on a new import screen with Add to Puzzles (10 packs at most; the same pack opened twice is kept once, with its progress). The Puzzles screen lists each pack in a fold with its own progress, plays a puzzle as an editor board (`pack` on the game screen, not resumable) and removes a pack. Pack puzzles pay no Shards, quests or season XP and touch no stats, since anyone can author an easy one. Not done: a rating or ordering by difficulty, and sharing the player's solved set.

The daily takes it in place of the rolls it names (the rolls are still all drawn, so the day's board, army, AI and court do not move), the weekly puts it under the week's modifier (the Monday's month; a modifier's own rules win) and the ladder lays it over its random army (`ladderConfig` takes a date). Each of the three screens names it with the days left in the month. No match rule changed; the balance guard test passes with the new daily and weekly configs. Not done: a ruleset on the Gauntlet, a shuffle in the Gauntlet or ladder, and a ghost or daily record made before this change no longer matches its rebuilt match (the rebuild now uses that date's month ruleset), so it is refused.
